# start 공통 원칙 동봉

## 배경

`start`는 플러그인의 공통 개발 원칙을 읽어야 하지만, 기존 `docs/spec/PRINCIPLE.md` 경로는
사용 중인 프로젝트를 기준으로 해석된다. 원칙을 스킬 배포물에 동봉하고 그 사본을 읽게 해,
프로젝트에 같은 문서가 없어도 시작 절차가 일관되게 동작하도록 한다.

## 설계

### 구조

- 공통 원칙 원본 → `docs/spec/PRINCIPLE.md` — 사람이 관리하는 플러그인 SSOT
- start 런타임 사본 → `skills/start/references/PRINCIPLE.md` — 소비 환경에서 읽는 동봉 리소스
- 동기화 검사 → `scripts/*-start-principle.sh` — 두 파일의 일치를 보장하는 유지보수 경계

기존 구조는 스킬별 보조 문서를 `references/`에 두는 방식을 이미 사용하므로 수용 가능하다.

## 계획

### T1: start 런타임 원칙을 동봉하고 로드 계약을 명시 ✅

공통 원칙의 배포 사본을 추가하고, `start`가 스킬 파일 기준 경로로 이를 반드시 읽도록 한다.
프로젝트의 동명 문서는 공통 원칙을 대체하지 않는 추가 규칙으로 정의한다.

### T2: 원본·사본 동기화 검증과 문서화 ✅

동기화 및 검사 명령을 제공하고 테스트로 연결한다. 플러그인 구조 문서와 변경 기록에
원본/런타임 사본의 책임을 기록한다.
