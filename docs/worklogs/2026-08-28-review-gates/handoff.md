# 반복 코드 피드백을 lint·독립 리뷰·구현 전 합의로 옮긴다

## 배경

사용자는 이름·책임·중복된 원본 때문에 코드를 이해하는 비용을 줄이려 한다.
문법 규칙은 프로젝트 lint로, 의미 판단은 구현자와 분리된 리뷰어로 옮기되 기존 서비스
전체를 정리하는 작업으로 확대하지 않는 것이 요구다. 필요한 공통 생명주기까지 불필요한
추상화로 일반화하지 않으며 실제 계약·소비자를 근거로 판단한다.

초기 PR은 검사 스크립트의 역할을 사용자에게 충분히 설명하지 않았고 아키텍처 문서에
사용법을 몰아넣었다. 구현 전 이해·합의를 담당할 align을 추가했지만, 문서 정리와 개명을
후속으로 남겨 같은 지적이 반복됐다. 사용자는 남은 피드백 전체 반영과 직접 작성을 승인했다.

## 해결 방법

기존 흐름에 align을 연결했다. start가 기존 구조·원인·설계를 준비하고 필요한 사전 구조
리뷰를 받는다. align은 현재·변경 후 동작과 버그 원인 추적을 사용자가 이해하도록
설명·질문하며, 이해도는 배점표 없이 종합적인 인상으로 85점 이상을 목표로 한다.
이해도 판단과 별개로 구현 범위에 대한 사용자 동의를 확인한다.
구현 → reviewer의 코드·구조·보안 검토 → 최종 검증 → PR로 이어진다.

기존 구조는 수용 가능하다. 상위 스킬만 reviewer로 바꾸고 세 하위 리뷰어를 유지한다.
프로젝트 lint가 규칙을 소유하고, 변경 수집기가 git 변경·snapshot을 제공하며,
check-lint-and-review가 실제 lint 결과와 구조 리뷰 이벤트를 현재 변경에 연결한다.
새 프레임워크·의존성·검사 조건은 추가하지 않는다.

문서도 책임별로 둔다. 아키텍처는 흐름·책임 인덱스, 스킬은 절차와 판단 기준,
스크립트 사용법과 프로젝트 설정은 각 담당 문서가 소유한다.
이미 삭제한 PRINCIPLE의 코드 작성·테스트·문서·대화 원칙은 해당 스킬에 유지한다.

## 결과

- 아키텍처를 162줄에서 54줄로 줄였다. 변경 수집 상세는 reviewer의 참고 문서,
  검사 실행·실패 해석과 설정 작성 원칙은 hooks의 두 문서로 옮겼다.
- skills/reviewer/SKILL.md로 개명하고 start·pr·explain·agents와 호출 경로를 갱신했다.
  코드 정확성 / 책임·이름 / 보안 위험으로 담당을 구분하고 중복 지적은 통합한다.
  구조 리뷰에는 문서의 책임도 검토하도록 명시했다.
- 스크립트는 collect-review-changes.mjs와 check-lint-and-review.mjs로 개명했다.
  검사 코드는 세션·턴 기록, 리뷰 기록, lint·리뷰 확인, CLI·오류 처리 흐름을 구분했다.
  설정 오류는 어느 필드가 잘못됐는지 알리고, 긴 메시지와 압축된 조건은 풀어 썼다.
  판정·반복 중단·리뷰 재사용 조건은 유지했다.
- PR 게시 전 검사에서 사용자 피드백 항목마다 실제 반영 근거를 대조한다.
  일부 완료를 전체 완료로 보고하지 않고 남긴 항목·이유를 명시한다.
  승인된 수정 후 검증·커밋·기존 브랜치 푸시 원칙과 기존 draft 설정을 유지한다.
- 2026-09-09 npm test 41/41 통과(49.9초). 테스트 변경은 새 실행 경로 두 줄뿐이며
  검증 조건은 바꾸지 않았다. 수정한 스킬 4개 형식 검사, 문서 상대 링크 42개,
  두 스크립트 문법 검사와 git diff --check를 통과했다.
- 독립 코드·구조·보안 검토에서 이번 변경이 만든 수정 필요 사항은 없었다.
  모든 작성은 메인이 직접 했고, 리뷰어는 읽기 전용으로 검토했다.

## 한계와 후속

이번 변경으로 남겨둔 문서 정리·개명·리뷰 역할·검사 코드 가독성 피드백을 반영했다.
mimeo 서비스 코드·제품 테스트·플러그인 설치본은 변경하지 않았다.
기존 lstack draft PR #24의 같은 브랜치를 갱신한다. ready 전환·merge·설치는 범위 밖이다.

이번 회귀 검증은 실제 Node CLI·임시 git과 테스트용 Claude 이벤트를 사용한다.
이전 구현에서는 실제 Claude CLI 통합 동작을 확인했지만 이번 변경 후 재실행하지 않았다.
align의 실제 대화 효과와 리뷰 판단 품질은 실사용에서 확인해야 하며,
사용자의 이해도를 실제로 평가한 것처럼 점수를 기록하지 않는다.

export·사용처 표는 정규식 후보 탐색이지 의미 판정이 아니다. 세션별 임시 검사 기록은
오래된 리뷰 재사용을 방지하지만 로컬 상태 위조를 막는 보안 경계는 아니다.
프로젝트 lint의 기존 부채와 범위 밖 지적은 보고하며 검사 대상이라는 이유로 수정하지 않는다.
