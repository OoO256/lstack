# 구현 전 이해·합의 중심으로 lstack 작업 흐름을 줄인다

## 배경

사용자는 현재 코드와 변경안, 이후 버그가 났을 때 확인할 곳을 이해하려 한다.
기존 PR은 이 목표에 lint·리뷰 완료 확인과 상태관리까지 함께 넣어, 사용자가 이해하고
검토해야 할 대상을 오히려 늘렸다. 사용자는 자동 확인을 제외하고 lint·리뷰를 수동으로
실행하기로 했으며 reflica 검사 도입·마이그레이션도 이번 범위에서 제외했다.

## 해결 방법

기존 스킬 구조로 수용 가능하다. 새 실행 장치 없이 역할과 연결을 정리한다.

```text
start (변경): 기존 구조·원인 조사 → 작은 범위의 설계
  → align (신설): 현재·변경 후 동작과 버그 추적 이해 → 구현 범위 합의
  → 구현·동작 확인 → 변경 결과 설명·공유 (pr, 변경)
  → 마무리할 때 compound → close (기존)

사용자가 요청할 때: lint / reviewer (개명·역할 구분) / show
```

설계는 start, 이해·합의는 align, 결과 공유는 pr이 소유한다. reviewer는 요청받은
설계·코드·구조·보안을 별도 context에서 검토하되 작업의 자동 단계가 아니다.
아키텍처는 이 흐름의 인덱스로 두고, 삭제한 PRINCIPLE의 작성 원칙은 담당 스킬에 둔다.

## 결과

- start·pr에서 lint·독립 리뷰 자동 실행과 완료 기록 요구를 제거했다. 기존 프로젝트의
  필수 검사·CI·브랜치 보호 규칙은 그대로 존중한다.
- 자동 완료 확인·변경 수집 스크립트와 전용 설정·사용법 문서·회귀 테스트를 삭제했다.
  해당 기능이 없어졌으므로 전용 테스트 실행 항목도 제거했다. 기존 nobs 알림 hook만 남긴다.
  삭제한 파일은 이전 커밋 cc5d713에서 복구할 수 있다.
- align은 현재·변경 후 동작과 버그 추적 이해를 확인한다. 이해도는 배점표 없이 종합적인
  85점 인상으로 판단하고 구현 동의는 따로 확인한다. 이미 이해·합의한 부분은 반복하지 않는다.
- 이름·역할·책임에 대한 작성 원칙과 구조 리뷰어는 유지한다. 전체 저장소를 정리하지 않고
  합의한 작은 범위를 구현하며 사용자가 확인할 동작과 위치를 설명한다.
- 2026-09-11: 수정한 스킬 4개 형식 검사, 활성 문서 상대 링크 26개와 JSON 4개 검사,
  nobs hook 구문·실행 확인, git diff --check를 통과했다. hook 설정은 origin/main과 같다.
  이번 변경의 lint·독립 리뷰는 실행하지 않았다.

## 한계와 후속

사용자가 승인한 범위 축소를 반영했다. 이번 대화에서 별도의 이해도 평가를 수행한 것으로
기록하지 않는다. align의 대화 효과와 수동 리뷰 판단 품질은 실사용에서 확인해야 한다.
정적 검사와 알림 실행 확인은 실제 Claude/Codex 대화 흐름의 검증을 대신하지 않는다.

lstack 기존 draft PR #24를 갱신한다. reflica 서비스 코드·제품 테스트와 설치된 플러그인은
수정하지 않았다. reflica 마이그레이션은 진행하지 않으며 기존 draft PR #562도 그대로 둔다.
PR의 ready 전환·merge·플러그인 설치는 범위 밖이다.
