# 다음 수정에서 결정 이유와 남은 고민을 이어간다

## 배경

[공통 사용자 경험과 선택 이유](../2026-09-11-align-code-reading/handoff.md)를 먼저 읽는다.
사용자는 lstack를 쓰다가 마음에 들지 않는 점을 다시 고칠 때, 이 대화의 맥락과 고민을 이어가길 원했다.
기존 handoff는 결정 이유를 요구하면서도 과정 기록 금지·최신 상태만 유지·짧은 배경을 강조했다.
실제 세 작업 기록도 구현 결과 중심이라, 다음 사람이 자동화 확대를 보류한 이유 등을 놓칠 수 있었다.

## 해결 방법

기존 구조는 수용 가능하다. handoff 스킬(변경)이 기록의 형식·판단 근거 보존을 소유하고,
compound의 피드백 참고 문서(변경)는 중복을 합칠 때 이유를 보존하고 조회 시 그 이유도 읽도록 연결한다.
공통 배경은 첫 작업 기록에, 독립 리뷰·피드백 재사용·이번 인계 개선의 결정은 각 기록에 둔다.

대화 전체 저장이나 별도 결정 장부는 읽기 부담과 관리 지점을 늘려 선택하지 않았다.
네 섹션 안에 선택 이유·중요한 대안·재검토 조건을 남기면 기존 start의 기록 조회로 이어갈 수 있다.
모든 실패를 일지로 쓰는 것이 아니라 이후 판단을 바꿀 경험만 보존한다. 옛 결론을 영구 금지로 만들지 않는다.

## 결과

- 사용자 경험·성공 기준, 선택·보류 이유, 합의·구현·검증의 구분, 열린 질문·재검토 조건을 작성 기준에 넣었다.
  상태 갱신이 이유 삭제로 이어지지 않게 하고, 원문 없이도 핵심 고민을 이해할 수 있게 했다.
- 이번 세 작업 기록에 실제 대화의 근거를 보완하고 상호 연결했다. #24 상태도 닫힘으로 갱신했다.
  사용자 동의는 이 기록 개선의 구현 허락이며 실제 코드 이해나 인계 효과 확인의 증거는 아니다.
- 검증: handoff 스킬 형식, 활성 문서와 이번 네 작업 기록의 상대 링크 42개,
  git diff --check 통과. 작성자가 결정 변경·보류 대안·연관 기록·원문 접근 불가 상황을
  지침과 기록에 대조해 확인했다. 독립 에이전트나 새 세션 실행 시험은 아니다.

## 한계와 후속

- #28 뒤에 쌓는 후속 PR이다. 앞선 PR 브랜치는 수정하지 않고 이 PR에 지침·기록 보완만 포함한다.
- 실제 새 세션이 이 기록만으로 고민을 이어가는지는 미검증이다. 다음 사용에서 이미 보류한 자동
  검증 장치를 이유 없이 재제안하는지, 대표 코드 합의의 효과·질문 부담 같은 남은 질문부터 시작하는지 확인한다.
- 연결된 기록이 너무 길거나 잘 발견되지 않으면 공통 배경 요약·참조 위치를 먼저 보완한다.
  이를 이유로 전체 세션 수집·새 문서 체계·자동 강제 장치를 바로 추가하지 않는다.
- lint·독립 리뷰·실제 에이전트 실행 시험은 하지 않았다. 제품 코드·테스트·hook·설치본은 변경하지 않았다.
