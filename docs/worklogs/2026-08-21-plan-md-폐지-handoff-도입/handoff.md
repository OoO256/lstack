# plan.md 폐지 → handoff.md 도입

## 배경

작업마다 worklog 에 `plan.md` 를 만들어 계획을 적었다. 문제는 계획을 읽으려면 파일을
따로 열어야 했다는 것 — 계획은 대화 중에 보고 바로 판단하고 싶은 것인데, 문서로 넘기면
흐름이 끊긴다.

원인은 문서의 역할이 섞여 있었다는 것이다. plan.md 는 "앞으로 할 일"(계획, 대화에서
소비되는 것)과 "남겨야 할 기록"(인계, 파일에 남아야 하는 것)을 한 파일에 담고 있었다.
전자를 파일로 만들면 매번 파일을 열게 된다.

## 해결 방법

두 역할을 분리한다. 계획은 채팅에 인라인으로만 제시하고, 파일로는 **인계장** 하나만 남긴다.
그래서 문서의 성격이 바뀐다: **계획서(앞을 보는 문서) → 인계장(뒤를 보는 문서).**
만드는 시점도 따라 바뀐다 — 작업 시작 시가 아니라 맥락을 남에게 넘기는 순간
(subagent 위임 전 · PR 전 · compact 전 · `/handoff` 호출).

handoff.md 목차는 탑다운 4섹션이다. 위에서 아래로 읽으면
"왜 → 어떻게 → 무엇이 됐나 → 뭐가 남았나" 가 된다:
`배경`(현재 상황 · 문제 · 원인) · `해결 방법`(as-is → to-be · 설계 · 이해 단위 → 모듈 매핑) ·
`결과`(바뀐 것 · 작업 중 결정 · 검증 방법) · `한계와 후속`.

이해 단위 → 파일 매핑:

- `skills/handoff/SKILL.md` — 목차·작성 규칙 SSOT + 발동 트리거.
  기존 `skills/write-plan-md/` 를 rename 해 그 자리를 그대로 이어받는다.
- `skills/start/SKILL.md` — 계획을 문서가 아니라 채팅으로 낸다. resume 시 읽는 대상도
  plan.md → handoff.md.
- `skills/pr/SKILL.md` — PR desc 의 소스가 plan.md → handoff.md. desc 를 쓰기 전에
  handoff.md 를 먼저 쓴다는 순서는 유지.
- `docs/spec/PRINCIPLE.md` · `docs/spec/ARCHITECTURE.md` · `CLAUDE.md` — 워크플로우 SSOT.
  "계획은 문서로 만들지 않는다" 를 규범으로 명시.

기존 구조는 이 변경을 그대로 수용했다 — 스킬 하나 rename + 참조 교체로 끝나서
선행 리팩토링은 필요하지 않았다.

## 결과

- **handoff.md 목차 확정**: 위 4섹션. 파일 하나만 두고 매번 덮어쓴다.
- **`write-plan-md` 스킬 → `handoff`**: 구조 SSOT 역할에 `/handoff` 직접 호출을 더했다.
- **워크플로우 참조 정리**: `start` 는 채팅 계획 제시로, `pr` 은 handoff.md 기준으로,
  `close` · `call-as-codex` 는 문구만 정합. spec 3개 문서에 "계획 문서 금지" 규범 추가.
- 이 문서 자체가 새 목차의 첫 적용 사례다.

**작업 중 결정 사항**

- *빈 섹션을 허용한다.* 작성 시점에 따라 계획 직후엔 `결과` 가, 완료 후엔 `한계와 후속` 이
  빈다. 시점별로 목차를 바꾸는 대신 "없음" 한 줄로 남기기로 했다 — plan.md 의 모드 전환을
  되살리지 않기 위해서다.
- *과거 plan.md 4개는 그대로 둔다.* 과거 기록이고 소급 변환은 가치가 없다.
- *목차를 5섹션에서 4섹션으로 한 번 줄였다.* 처음엔 `결과`/`남은 작업` 을 나눴는데,
  완료할 때마다 항목을 옮겨야 해서 탑다운 4섹션으로 통합했다.

**검증 방법**

`grep -rn "plan\.md\|write-plan-md" CLAUDE.md docs/spec/ skills/ commands/ agents/ hooks/`
가 아무것도 잡지 않으면 참조 정리가 끝난 것이다 (과거 worklog 는 검색 범위에서 제외).

## 한계와 후속

- `docs/worklogs/` 에는 당분간 plan.md 와 handoff.md 두 형식이 섞여 있다.
- 목차가 SSOT(`skills/handoff/`) 외에 `ARCHITECTURE.md` · `CLAUDE.md` 에도 요약으로
  중복된다. plan.md 때와 같은 관례를 유지했지만, 목차를 또 바꾸면 세 곳을 함께 고쳐야 한다.
- 플러그인 캐시(설치본)는 머지 후 업데이트해야 새 규칙이 실제 세션에 적용된다.
