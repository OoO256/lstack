# 구조 우선 설계 — 사람이 이해하기 쉬운 코드 구조 의식 심기

## 배경

lstack 에이전트는 지엽적 코드는 잘 작성하지만, 사람이 이해하기 쉬운 **구조**(추상화 단위 분해,
응집도/결합도, 위계)를 설계 시점부터 고려하는 의식이 약하다.

- as-is: 의도 8이 응집도/결합도·SRP 를 언급하지만, "사람의 이해 단위 → 모듈 1:1 대응"과
  tidy-first(기존 구조가 안 맞으면 선행 리팩토링) 관점이 없다. plan 착수·PR 어디에도
  구조를 점검하는 지점이 없다.
- to-be: 가이드(의도 8)에 구조 의식을 명시하고, plan 착수 시 구조 판단을 유도하고,
  /pr 에서 전체 diff 구조 스캔으로 마무리 점검한다. 강제 게이트가 아니라 판단 유도 —
  얇은 하니스 철학 유지.

레퍼런스: <https://frontend-fundamentals.com/code-quality/code/>

## 계획

### T1: PRINCIPLE.md 의도 8 확장 — 멘탈 모델 1:1 + tidy-first ✅
"코드 구조는 사람의 이해를 위한 것" 프레임으로 재서술 — 이해 단위 분해 → 모듈/파일 1:1 대응,
tidy-first 를 계획에 포함, frontend-fundamentals 레퍼런스 링크.

### T2: start + write-plan-md — plan 착수 시 구조 판단 ✅
start 는 계획 분해 전에 구조 판단(이해 단위·1:1 대응·기존 구조 적합성)을 먼저 하도록.
write-plan-md 에 선택적 `## 설계 › ### 구조` 형식(단위 → 모듈 매핑 + 적합성 판정) 정의.
구조 변화 없는 작업은 쓰지 않음 — 남발 금지 원칙 유지.

### T3: pr — 구조 스캔 ✅
change-detector 스캔과 나란한 섹션으로, push 전 전체 branch diff 를 의도 8 기준
(1:1 대응 / 덧붙이기로 인한 응집도 훼손 / 미룬 리팩토링 흔적)으로 훑고 findings 를
채팅에 보고. 임의 수정 금지, 발견 없으면 한 줄로 통과.

### T4: ARCHITECTURE.md 동기화 ✅
스킬 표(start·pr 행)와 plan.md 서술에 구조 판단·구조 스캔 반영.

## 향후 과제
- 구조 스캔이 노이즈(사소한 지적 남발)를 내면 기준을 조정한다 — 사용하면서 관찰.
