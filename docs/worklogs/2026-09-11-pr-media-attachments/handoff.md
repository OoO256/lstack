# PR에 가벼운 as-is/to-be 미디어를 자동 첨부한다

## 배경

UI 변경을 설명하는 이미지와 영상을 PR에 넣으려면 사람이 브라우저에 파일을 드래그해야 했다.
기존 lstack은 브라우저 코멘트 입력창을 업로드 경로로 자동화했지만, 로그인 세션에 의존하고 동작
변화를 영상으로 보여 주는 기준도 없었다.

## 해결 방법

GitHub CLI 2.99 이상이 제공하는 `--attach`를 업로드 경로로 사용한다. `/show`는 비교 자료 생성,
`/pr`은 본문 배치·업로드·검증을 맡으며 기존 스킬 구조가 이 책임을 수용할 수 있어 별도 스킬은
추가하지 않았다.

정적인 UI 변화는 가벼운 JPG, 상호작용·애니메이션 변화는 짧은 H.264 MP4 또는 GIF로 남긴다.
두 경우 모두 as-is와 to-be를 같은 조건으로 비교하며, 미디어는 현재 worktree의
`.lstack/pr-media/`에 두고 Git에는 포함하지 않는다.

## 결과

- 브라우저 업로드 절차를 `gh pr create/edit --attach` 절차로 교체했다. 본문의 로컬 경로가
  GitHub 첨부 URL로 바뀌었는지 확인하고 부분 실패 시 생성된 PR에 누락 파일만 보완한다.
- JPG는 품질 70 안팎·가로 1440px 이하·1MB 이하, 동작 미디어는 720p 이하·10MB 이하를 목표로
  삼고 압축 결과를 직접 판독하도록 했다.
- as-is가 없을 때 base용 임시 worktree에서 캡처해 현재 작업공간을 되돌리지 않도록 했다.
- `pr`, `show`, `handoff`, 개발 원칙과 changelog의 미디어 기준을 일치시켰다.

검증은 스킬 frontmatter, 내부 링크, 미완성 placeholder, `git diff --check`를 확인했다. 로컬
GitHub CLI를 2.100.0으로 올리고 `gh pr create/edit --attach` 옵션도 확인했다.

## 한계와 후속

실제 첨부 업로드는 PR 생성·수정이 필요한 외부 변경이므로 이 구현 검증에서는 실행하지 않았다.
