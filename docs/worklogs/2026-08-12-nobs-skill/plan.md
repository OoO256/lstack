# nobs — 응답 작성 규칙을 하니스에 고정

## 배경

응답 작성 규칙(결론 먼저 · 신규 용어 금지 · 최대한 짧게)이 사용자 개인 `~/.claude/CLAUDE.md` 에만 있었다.
그래서 (1) 다른 머신·다른 사람이 lstack 만 설치하면 규칙이 따라오지 않고, (2) 규칙이 SSOT 로 참조·개선될 지점이 없었다.
lstack 안으로 옮겨 플러그인과 함께 배포되게 한다.

"에이전트가 사용자에게 말할 때 항상 적용"이 요구사항인데, 스킬은 모델이 description 을 보고 스스로 호출하는 방식이라
"항상"이 보장되지 않는다. 따라서 **스킬(규칙 전문 SSOT) + UserPromptSubmit 훅(매 턴 한 줄 주입)** 두 겹으로 둔다.

## AS-IS → TO-BE

| 축 | AS-IS | TO-BE |
|---|---|---|
| 규칙 위치 | 사용자 개인 `~/.claude/CLAUDE.md` 만 | `skills/nobs/SKILL.md` (플러그인과 함께 배포) |
| 적용 보장 | CLAUDE.md 로딩에 의존 | 훅이 매 턴 주입 → 100% |
| 각주 형식 | `<각주>` 블록에 부차 내용 뭉치 | 참조형 — 본문 `[1]` 마커 + 뒤에 `[1] 내용` |

## 구현 원칙

- **훅은 한 줄만 주입한다.** 매 턴 비용이 드는 자리이므로 규칙 전문을 넣지 않고, 압축한 한 줄과 SSOT 경로만 둔다.
  전문이 필요하면 스킬을 호출한다.
- **각주는 참조형.** 본문은 마커로 짧게 유지하고 상세는 아래로 내린다.
  본문에 붙일 anchor 가 없는 첨언은 억지로 만들지 않고 마커 없이 `-` bullet 으로 붙인다.
- **훅 문장과 스킬 본문은 같이 고친다.** 어긋나면 매 턴 주입되는 쪽이 이겨서 스킬이 죽은 문서가 된다.

## 남은 한계

- 사용자 개인 `~/.claude/CLAUDE.md` 에도 같은 규칙이 남아 있다 (이 저장소 밖이라 PR 범위 외).
  중복이 신경 쓰이면 개인 쪽을 `skills/nobs` 참조로 줄일 수 있다.
- 훅은 Claude Code 세션 시작(플러그인 로드) 시점부터 적용된다 — 기존 세션엔 즉시 반영되지 않는다.
