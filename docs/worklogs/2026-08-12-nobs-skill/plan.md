# nobs — 응답 작성 규칙을 하니스에 고정

## 배경

응답 작성 규칙(결론 먼저 · 신규 용어 금지 · 최대한 짧게)이 사용자 개인 `~/.claude/CLAUDE.md` 에만 있었다.
그래서 lstack 을 설치한 다른 환경엔 규칙이 따라오지 않고, 규칙을 참조·개선할 SSOT 지점도 없었다.

| 축 | as-is | to-be |
|---|---|---|
| 규칙 위치 | 개인 `~/.claude/CLAUDE.md` 만 | `skills/nobs/SKILL.md` (플러그인과 함께 배포) |
| 적용 보장 | CLAUDE.md 로딩에 의존 | 훅이 매 턴 주입 |
| 각주 형식 | `<각주>` 블록에 부차 내용 뭉치 | 참조형 — 본문 `[1]` 마커 + 뒤에 `[1] 내용` |

## 설계

"에이전트가 사용자에게 말할 때 항상 적용"이 요구사항인데, 스킬은 모델이 description 을 보고 스스로
호출하는 방식이라 "항상"이 보장되지 않는다. 그래서 **스킬(규칙 전문 SSOT) + UserPromptSubmit 훅
(매 턴 압축된 한 줄 주입)** 두 겹으로 둔다.

훅에 규칙 전문을 넣지 않는 이유: 매 턴 토큰이 드는 자리다. 한 줄과 SSOT 경로만 두고,
전문이 필요하면 스킬을 호출한다.

**리스크** — 훅 문장과 스킬 본문이 어긋나면 매 턴 주입되는 훅이 이겨서 스킬이 죽은 문서가 된다.
둘은 항상 같이 고친다.

## 계획

### T1: nobs 스킬 — 응답 규칙 SSOT ✅

`skills/nobs/SKILL.md`. 결론 먼저(분석은 현/원/대/사, 아니어도 `[문제]` `[결론]` 식 구조화) ·
신규 용어 금지 · 최대한 짧게 · 정보는 중요도 순. 응답 전 체크리스트 포함.

### T2: UserPromptSubmit 훅 — 매 턴 적용 보장 ✅

`hooks/scripts/nobs-reminder.sh` 가 규칙 압축본 한 줄을 stdout 으로 출력, `hooks/hooks.json` 에 등록.
v2 는 hookless 였으나 "항상 적용"은 훅 없이 불가능해서 이 하나만 둔다 — 워크플로우 게이트용 훅은 여전히 없다.

### T3: 각주 형식을 참조형으로 ✅

본문엔 `[1]` 마커만, 상세는 본문 뒤 `[1] 내용`. 본문에 붙일 자리가 없는 첨언은 억지로 anchor 를
만들지 않고 마커 없이 `-` bullet 으로 붙인다.

## 향후 과제

- 개인 `~/.claude/CLAUDE.md` 에 같은 규칙이 남아 있다 (이 저장소 밖). 중복이 신경 쓰이면 개인 쪽을 `skills/nobs` 참조로 줄일 수 있다.
