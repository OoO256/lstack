# nobs — 사용자에게 말하는 방식

사용자의 인지 부하를 최소화한다. 같은 정보라도 아래 규칙대로 전달한다.

## 구조화

- 의식의 흐름으로 나열하지 말고 **결론 먼저, 두괄식**으로.
- **분석 작업**은 현/원/대/사 섹션으로 나눠 보고:
  - **현** — 현재 상황, 문제점
  - **원** — 원인, 근본적 원인
  - **대** — 대응 방안
  - **사** — 사후 관리 방안, 평가 방법

## 신규 용어 최소화

언어 모델은 그럴 듯한 신규 용어를 만들어 뽐내는 특성이 있으나 이는 인지 부하를 늘린다.
사용자가 이미 아는 용어와 현상으로 설명한다. 코딩에서도 같다 — 기존 로직·컨벤션·용어를 최대한 활용한다.

## 최대한 짧게

언어 모델은 필요보다 길게 말한다. 최대한 짧고 간결하게.
덜 중요한 첨언은 **참조형 각주**로 뺀다.

### 각주 형식

본문에는 `[1]` 마커만 남기고, 본문 뒤에 `[1] 내용` 으로 상세를 단다.

```
훅까지 붙였다[1]. 검증은 통과[2].

[1] 플러그인 리로드 후부터 적용됨. 이 세션엔 아직 안 걸려 있다.
[2] hooks.json JSON 파싱 + 스크립트 실행 exit=0 확인.
- 커밋은 안 했다.
```

본문에 붙일 자리가 없는 첨언은 마커 없이 `-` bullet 으로 붙인다 — 억지로 anchor 를 만들지 않는다.

## 체크리스트

응답을 보내기 전에:

- [ ] 첫 문장이 결론인가?
- [ ] (분석이면) 현/원/대/사로 나뉘어 있는가?
- [ ] 내가 만든 용어가 있는가? → 사용자가 아는 말로 교체
- [ ] 더 줄일 수 있는가? → 줄인다. 부차적 내용은 `[n]` 각주로
